# 計算ロジックの地図

計算ロジック・資産クラス・配分を変えるときに、統括役（メインの Claude Code）が最初に読む。
サブエージェント（app-implementer／app-verifier／app-reviewer）には、ここから該当するツールの節と「共通の定義」だけを渡す。

- 設計書は `../../Docs/設計書_v7_25_main.md`（以下「設計書」。版が上がったらこの行を直す）
- 節番号は設計書の見出し。アプリの `CLAUDE.md` の「アーキテクチャの要点」にも運用上の注意がある

## 共通の定義（3ツールが共有する。ここを変えると全部に効く）

| もの | 場所 | 使うところ |

| モデル配分（Lv1〜7） | `src/lib/rb/types.ts` の `MODEL_ALLOCATIONS`・`MODEL_META` | /rb・/portfolio・/risk の「このPFを採用する」 |
| 最適PF（DB） | `optimal_portfolios`（`scripts/optimize_portfolios.py --apply` が書く。新興国REITは `EXCLUDED_FROM_MODEL` でモデル配分から除外、v7.25） | `MODEL_ALLOCATIONS` と手で同期 |

### 対で直すもの
- `optimize_portfolios.py` の結果を DB に反映したら → `MODEL_ALLOCATIONS`・`MODEL_META` も同期し、`python3 scripts/check_model_levels.py` で照合（exit 1 なら不一致）
- `EFF_UPPER` を変えたら → `classifyRiskLevel7` も（`src/logic/pfSimple.test.ts`）
- 資産クラスを足す・変えたら → `rb/types.ts`（`portfolioAllocation.ts` は自動で追随、色だけ足す）、/pf の `CATEGORIES`、/ma の `MaAssetClass`（下）、DB のカラム、教材（実践4 のワークシート・スライド）
- モデル配分が変わったら → 実践4 系の教材のサンプル（`wealth-program/`）も点検（FI_project の CLAUDE.md「教訓」）
- 暗号資産の見分け方のリスト（`src/lib/rb/crypto.ts`）を変えたら → FI_project `personal-monitor/monitor/crypto.py` 側のリストも（同じ中身）

## /rb リバランス

| | |
|---|---|
| 計算 | `src/lib/rb/logic.ts`（乖離 `calculateDeviation`、買い増し／売却の調整、期間、緊急資金と /ma の待機資金の別枠（投資可能な現金＝現金−緊急資金−待機資金、0 で止める。`calculateEmergencyFund`・`applyEmergencyFund`、FI_project #118）、`simulateMonthly`） |
| /ma の待機資金 | `src/lib/rb/maReserve.ts` の `pickMaReserve`（本人の行＝台帳 `ma_ledger` の最後の行の実効の月末残高（`MaReserveRow.ledger_balance`、#140）。台帳が空・読めなければ `user_ma_settings.reserve_balance`、ほかの人＝この端末の /ma の localStorage。暗号文は読まない。読めなければ 0 として計算し画面に出す）。読むのは `src/lib/rb/db.ts` の `fetchMaReserveRow`。/rb からは書き換えない。/ma の待機資金の持ち方（D-007 の台帳方式など）を変えたら、ここの読み先も直す |
| 積立のみ | `estimateMonthsToRebalance(holdings, target, M)`（FI_project #76、2026-11-12）：売らずに目標配分に着く最小の月数 n。目標より多い現金以外の資産クラス i が 今の額_i ≤ w_i×(T＋M×n) を満たす最小の n（1以上、`ceil((今の額_i/w_i − T)/M)`、誤差 1e-9）。超過クラスが無くても目標どおりでなければ1、目標どおり（全クラスの差が1円未満）なら0、M≤0 なら null。現金は取り崩して不足へ回せるので月数を縛らない。現金以外で目標0%なのに保有があれば積立だけでは戻らない（`{ unreachable: 資産クラス名 }`、画面は `calculateAddAdjustment` で今月の積立先だけ出す。#79：新しい総資産 T＋M に対する不足額の比で M を配り、今多いクラス（h>w×T）・目標0%は対象外、1,000円単位で端数はいちばん多い積立先）。毎月の配分は `calculatePeriod(holdings, target, n, M)` を最小の n で使う（売却は0） |
| 期間指定 | `calculatePeriod(holdings, target, N, M)`（FI_project #74、2026-11-12）：完了期間 N と毎月の積立 M の両方を使う。目標額は N か月後の総資産 E＝T＋M×N に目標配分を掛けた額。売却＝max(0, 今−目標)、買い＝max(0, 目標−今)、現金は売却ではなく取り崩し（または現金のまま置く）、いつもの積立で不足を先に埋め、足りない分だけを売る（売却を最小化）。#79（2026-11-12）：毎月の売却（各クラス、`monthlySells`）・取り崩し・現金に残す額は総額÷N を1,000円単位に四捨五入（売却総額 `sellTotals` は丸めない。残す額は M＋取り崩し＋売却が上限、毎月の売却が0になるクラスは `periodSellRows` に出さない）。毎月の買いの合計 B＝M＋取り崩し＋売却−残す額を、買いの対象（現金以外で w>0 かつ h≤w×T）の不足額 max(0, w×E−h) の比で配り1,000円単位、端数はいちばん多い買い（対象の不足額が0なら目標額−今の額が正のクラスすべて）。今多いクラスは終わったときに目標をわずかに下回ってよい。`simulateMonthly` はこの毎月の額をそのまま N か月続けた推移（`MonthlyProjection.tsx`）。`calculatePeriodByMonths` は M＝0 の呼び出し |
| 乖離の段階と戻す目安 | 段階は `getSeverity`（2・5・10%、変えない）。戻す目安は `REBALANCE_THRESHOLDS`（5%標準／10%）・`isOverThreshold`（\|乖離\| が目安以上）・`countOverThreshold`。選んだ目安はブラウザ（localStorage `rb.rebalanceThreshold`）だけに保存、DB には持たない |
| 投信の取り込み | `src/lib/rb/mfParser.ts`（マネーフォワードの「資産」ページの貼り付けテキスト。区分名は `allocator.ts` が読む表記に正規化。資産クラスの合計がマイナスなら `clampNegativeHoldings` で0に）、`src/lib/rb/allocator.ts`（`fund_master` で資産クラスに振り分け。cash も `fund_master` から入り、緊急資金の差し引きの対象になる）。暗号資産（預金の区分の行を `src/lib/rb/crypto.ts` の `isCryptoHolding` で判定）は cash に入れず配分の計算の対象外とし（`excluded`、合計は `sumExcludedCrypto`。外した行の名前も表示（`excludedCryptoNames`））、区分の合計の照合には含める |
| 型・定数 | `src/lib/rb/types.ts`（共通の定義を兼ねる） |
| DB | `src/lib/rb/db.ts`（目標配分と緊急資金の月数だけ。残高・生活費はサーバーに送らない、D-065・FI_project #109） |
| 残高・生活費の保存 | ブラウザ（localStorage `fi.rb.amounts.v1.<userId>`）だけ。`src/lib/rb/localAmounts.ts`（`saveLocalHoldings`・`saveLocalLivingCost`・`loadRbAmounts`）。前に DB に保存した生活費は開いたとき `planLivingCostMove` でブラウザへ移してから DB 側を null に。`rb_snapshots` は 047 で割合（`weight`）と指数（`total_index`、最初の回＝100）に置き換え、金額は持たない（案A の作り直しまで画面は書かない） |
| テスト | `src/lib/rb/logic.test.ts`、`src/lib/rb/maReserve.test.ts`、`src/lib/rb/db.test.ts`、`src/lib/rb/localAmounts.test.ts`、`src/lib/rb/allocator.test.ts`、`src/lib/rb/mfParser.test.ts`（見本は `__fixtures__/mf_assets_sample.txt` と暗号資産入りの `mf_assets_crypto_sample.txt`、架空のデータ）、`src/lib/rb/crypto.test.ts` |
