# 計算ロジックの地図

計算ロジック・資産クラス・配分を変えるときに、統括役（メインの Claude Code）が最初に読む。
サブエージェント（app-implementer／app-verifier／app-reviewer）には、ここから該当するツールの節と「共通の定義」だけを渡す。

- 設計書は `../../Docs/設計書_v7_24_main.md`（以下「設計書」。版が上がったらこの行を直す）
- 節番号は設計書の見出し。アプリの `CLAUDE.md` の「アーキテクチャの要点」にも運用上の注意がある

## 共通の定義（3ツールが共有する。ここを変えると全部に効く）

| もの | 場所 | 使うところ |
|---|---|---|
| 13資産クラス（My Index 定義） | `src/lib/rb/types.ts` の `ASSET_CLASSES`・`AssetClassKey` | /rb・/portfolio・/risk の採用ボタン |
| 資産クラス（別定義・11クラス） | `src/logic/portfolioAllocation.ts` の `ASSET_CLASSES`（`commodity`・`emerging_reit` が無い） | /pf（PF診断）・旧リスク診断（`components/assessment/`） |
| モデル配分（Lv1〜7） | `src/lib/rb/types.ts` の `MODEL_ALLOCATIONS`・`MODEL_META` | /rb・/portfolio・/risk の「このPFを採用する」 |
| 最適PF（DB） | `risk_model_portfolios`（`scripts/optimize_portfolios.py --apply` が書く） | `MODEL_ALLOCATIONS` と手で同期 |
| リスクレベルの判定 | `src/logic/pfSimple.ts` の `classifyRiskLevel7`（しきい値は `optimize_portfolios.py` の `EFF_UPPER` と対） | /portfolio・/pf |
| 期待リターン・リスク・相関 | DB `asset_class_params`（`src/lib/assetClassParamsDb.ts`）。取得失敗時は `src/logic/portfolioDiagnosis.ts` の `FALLBACK_*` | /portfolio・/pf・`optimize_portfolios.py` |
| 目標配分（採用PF） | `user_rb_settings`（`src/lib/rb/db.ts` の `saveTargetAllocation`／`fetchTargetAllocation`） | /risk が保存、/rb が読む |

設計書：v7.22「新しいモデル配分」「リスクレベル境界を 20% → 16.5% に変更」「単一資産の上限を新設」、v7.24（モデル配分のレベル食い違い）、§13-64（採用PF＝全ツールのアンカー）

### 対で直すもの
- `optimize_portfolios.py` の結果を DB に反映したら → `MODEL_ALLOCATIONS`・`MODEL_META` も同期し、`python3 scripts/check_model_levels.py` で照合（exit 1 なら不一致）
- `EFF_UPPER` を変えたら → `classifyRiskLevel7` も（`src/logic/pfSimple.test.ts`）
- 資産クラスを足す・変えたら → `rb/types.ts` と `logic/portfolioAllocation.ts` の2か所、/ma の `MaAssetClass`（下）、DB のカラム、教材（実践4 のワークシート・スライド）
- モデル配分が変わったら → 実践4 系の教材のサンプル（`wealth-program/`）も点検（FI_project の CLAUDE.md「教訓」）
